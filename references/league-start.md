# Incoming league-start guides

## Review loop

1. Establish the target league/patch, mode, desired content and playstyle. Carry forward known user preferences; leave unknown preferences explicit rather than repeatedly asking broad questions.
2. Discover recent original creator guides and revisions. Search by patch, archetype and author; check both publication and update dates. Group renamed versions of the same build together.
3. Trace each candidate's skill, ascendancy, item, crafting and temporary-power dependencies through current notes and PoB/database records. Read the actual leveling progression and mandatory-item fallback.
4. Audit the relevant PoB configurations using the PoB reference. Check early trade availability or SSF acquisition separately from final gear. Treat projected costs as estimates until the market exists.
5. Update the dated shortlist with the decision and changed evidence. Prefer a few actionable recommendations; preserve rejected candidates and reasons in the ledger so future reviews do not repeat the same work.

## Candidate record

Use a project research file when ongoing tracking is requested. A candidate entry should include:

```markdown
### Build name / ascendancy — creator
Status: discovered | awaiting update | reviewed-provisional | launch-ready | rejected
Reviewed: YYYY-MM-DD; target patch/mode:
Original guide / video / written guide:
Published / revised:
PoB URL / retrieved date / PoB or tree version:
Evidence inspected: notes | transcript | footage | export | local recalculation
Playstyle and intended farming:
Campaign skill and transition:
Mandatory gem/items and fallback:
First-map gear, links and level:
Upgrade sequence and realistic endpoint:
Damage assumptions and boss uptime:
Defenses, recovery, resource sustain and failure cases:
Patch dependencies / removed temporary power:
Budget basis: observed listings (league/time) | estimate | unknown
SSF/Hardcore suitability and restrictions:
Unresolved questions:
Verdict and confidence:
Next review trigger:
```

Use `launch-ready` only when the campaign-to-maps path and essential dependencies have adequate evidence for the chosen mode. It does not mean proven in an unreleased league. A guide with a 3.30 title and a 3.29 export is not automatically invalid; audit what is unchanged, changed or not yet modeled and mark it provisional when consequential uncertainty remains.

## Review triggers

Refresh affected candidates when GGG amends relevant notes, a creator revises the guide/export, PoB implements a missing mechanic, a required item's acquisition changes, or live prices invalidate the starter budget. Avoid rereading unaffected material. At launch, replace predictions with observed early-map reports, market availability and dated ladder snapshots where available.

Do not invent numerical rankings, damage tests, prices or clear speeds. Require measured evidence before presenting performance charts. A video's expensive showcase does not establish starter viability. Prefer a documented four/five-link early-map setup with ordinary gear and clear progression over unsupported headline damage.

Review requests can be short: "Review this PoB for league start", "Refresh the starter shortlist", "Check what changed since our last review", or "Find starters for SSF mapping". Monitoring is on demand unless the user separately requests and configures scheduled checks.
